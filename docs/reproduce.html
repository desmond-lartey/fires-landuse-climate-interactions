Reproduce this analysis

Run the pipeline on your own Earth Engine project

Every asset path in the scripts is namespaced under projects/ee-desmond/assets/... — replace that prefix with your own Earth Engine cloud project before running anything. The order below matches script numbering on the GEE scripts page.

Prerequisites

  • A Google Earth Engine account with a cloud project, and access to the Code Editor.
  • Your own 15-park (or however many you're analysing) boundary shapefile, uploaded as an EE FeatureCollection asset with at least one identifying name field.
  • A study-area geometry drawn or imported in the Code Editor, covering all parks with margin for the 20 km buffers.
  • Python 3.10+ with pandas, numpy, statsmodels, matplotlib, and geopandas for the downstream regression/figure step.

Run the Earth Engine pipeline, in order

1

Burned-area composites

Paste gee-full-script/01_burned_area_composites.js into the Code Editor with your geometry defined. Run and confirm 12 Drive exports queue in the Tasks tab.

2

Import park boundaries

Upload your park shapefile as an asset and update the NewParkMerged path in every subsequent script to point at it.

3

Buffer disaggregation

Run 02_buffer_disaggregation.js once the six monthly assets from Step 1 finish exporting and are re-imported as assets.

4

Land-cover harmonisation

Run 03_landcover_harmonisation.js to confirm the GLAD/ESRI remap produces sensible layers on the map before using it inside the combined pipeline.

5

Combined pipeline

Run 05_combined_pipeline.js, which calls the climate and land-cover functions internally. This is the long-running export — expect it to take longer than the individual steps.

6

Seasonal totals

Run 05b_seasonal_fire_rainfall.js separately to produce the dry/wet seasonal table used for the Step 5 regressions.

Export quotasEarth Engine has per-user concurrent task limits. Run the 12 monthly exports in Step 1 in batches if you hit a queueing error, and expect the combined pipeline (Step 5) to be the slowest single export given it re-runs the climate zonal mean for every park × buffer × year.

Pull exports into the repository

All Export.table.toDrive calls write to a GEE folder in Google Drive. Download the resulting CSVs into DATA_DIR/, keeping the export description as the filename so the pipeline scripts can find them without editing paths:

expected files in DATA_DIR/text
DATA_DIR/
├── BurnedAreaAndFrequencyResults.csv
├── BurnedArea_LC_Climate_ESRI_GLAD_2000_2024_corrected2.csv
└── BurnedArea_ERA5Seasonal_2004_2024.csv

Run the Python analysis

The pipeline/ folder cleans the raw exports (parsing the LandUseDistribution JSON column, joining benchmark-year land cover onto the per-buffer burn table, deriving dry/wet season totals) and fits the OLS regressions described in Methodology → Step 5:

terminalbash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 1. Clean + join the raw exports
python pipeline/01_clean_join.py --in DATA_DIR --out outputs/

# 2. Fit the fire-rainfall OLS regressions (within-year, multi-year, pooled)
python pipeline/02_fit_regressions.py --in outputs/BurnedArea_LC_Climate_joined.csv

# 3. Render the figures referenced on the Results page
python pipeline/03_make_figures.py --in outputs/ --out figures/

Each pipeline/ script is a plain script, not a notebook — run with --help for its full argument list. Exploratory notebooks that informed but are not required by the final pipeline live in notebooks/ and are not part of the reproducible path.

Common issues

SymptomLikely causeFix
User memory limit exceeded in reduceRegionBuffer geometry too large at 500 m/30 m scale for the default reducer memoryAdd or raise maxPixels (already 1e13 in the provided scripts) and/or reduce at a coarser scale temporarily to debug
Land-cover histogram keys don't match expected 1–9A GLAD or ESRI code wasn't included in the remap dictionaryCheck the unabridged gladToEsri dictionary in gee-full-script/; add any missing native codes
Seasonal script times out client-sideThe nested for loop calls .getInfo() for list lengths on every iterationCache parkList.size().getInfo() and years.size().getInfo() once before the loop, or refactor to server-side .map()
Precipitation values look 1000× too smallERA5-Land precipitation is natively in metres, not millimetresConfirm the .multiply(1000) conversion is present before export
