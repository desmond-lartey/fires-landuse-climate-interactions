Data layers

Four remotely sensed inputs, one joined output table

Everything downstream of Earth Engine — the regressions, figures, and tables in the manuscript — is built from a single wide CSV keyed by park, buffer distance, and year. This page documents the four source layers (Table 3) and the resulting schema.

Source datasets (Table 3)

LayerSourceResolutionTemporal coverage
Burned area MODIS MCD64A1 Collection 6.1 — monthly global burned area from 500 m surface reflectance and active-fire detections (Giglio et al., 2018) 500 m 2004–2024
Land cover GLAD GLCLU2020 v2 (Potapov et al., 2022) harmonised with ESRI Global 10 m Annual LULC (Karra et al., 2021) 30 m / 10 m 2000–2020 / 2017–2024
Climate ERA5-Land Monthly Aggregates, ECMWF/Copernicus Climate Change Service (C3S, 2018) — precipitation, air temperature, wind ~0.25° (~25 km); native grid ~11 km 2004–2024
Park boundaries WDPA-derived polygons, merged into one authors' shapefile with an ORIG_NAME attribute vector static

Output CSV schema

The final export (BurnedArea_LC_Climate_ESRI_GLAD_2000_2024_corrected2.csv) has one row per (park, buffer distance, year) combination — 15 parks × 5 buffers × 9 benchmark years = 675 rows in the land-cover-linked table; the fully seasonal version (BurnedArea_ERA5Seasonal_2004_2024.csv) has one row per (park, year, season) — 15 × 21 × 2 = 630 rows.

ColumnTypeDescription
ORIG_NAMEstringPark name, matches the study-area table
YearintBenchmark year (land-cover table) or calendar year (seasonal table)
Buffer_km / Bufferdistfloat0, 5, 10, 15, or 20
BufferArea_sqkmfloatGeodesic area of the buffer polygon
{Mon}_BurnFrequencyintSummed pixel-years burned for that month, one column per Oct–Mar
{Mon}_BurnedArea_sqkmfloatBurn frequency converted to km² at 500 m/pixel
TotalPixelsfloatBuffer area divided by pixel area at the relevant resolution
AvgBurnPerPixelfloatSummed monthly frequencies ÷ TotalPixels
AvgBurnPerYearfloatAvgBurnPerPixel ÷ 22 (climatology length)
LandUseDistributiondict/JSONClass → pixel-count histogram from frequencyHistogram(), 30 m
ERA5_Tmean_C, _Tmin_C, _Tmax_C, _Tdew_CfloatZonal mean temperature variables, °C
ERA5_Precip_mmfloatZonal mean total precipitation, mm
ERA5_SurfacePressure_hPafloatZonal mean surface pressure, hPa
ERA5_WindU, ERA5_WindVfloatZonal mean 10 m wind components, m/s
SeasonstringDry (Oct–Mar) or Wet (Apr–Sep) — seasonal table only
BurnedArea_km2, Rainfall_mmfloatSeasonal totals — seasonal table only

frequencyHistogram outputLandUseDistribution is exported as a nested dictionary keyed by class code ("1"…"9") with pixel counts as values. Divide each value by the row's TotalPixels to get a class fraction, or multiply by 0.0009 km² (30 m pixel area) to get class area.

Repository data layout

On disk, raw exports, cleaned tables, and figures are kept in separate top-level folders so the pipeline scripts never read from or write into a directory meant for a different stage:

repository layouttext
fires-landuse-climate-interactions/
├── DATA_DIR/              # raw CSV/SHP exports pulled from Google Drive → GEE
├── gee-full-script/        # canonical Earth Engine scripts (source of truth)
├── pipeline/                # Python: cleaning, joins, regressions, figure generation
├── notebooks/                # exploratory notebooks (kept out of the pipeline path)
├── outputs/                  # cleaned/joined CSVs consumed by pipeline scripts
├── figures/                  # rendered PNG/SVG figures referenced in the manuscript
├── docs/                     # this GitHub Pages site
├── archive/                   # superseded scripts and one-off exploration, kept for provenance
└── ecological_zones_5class/  # earlier 5-class zoning attempt, retained for reference

See Reproduce this analysis for the exact commands used to move data from DATA_DIR/ through pipeline/ to outputs/ and figures/.
